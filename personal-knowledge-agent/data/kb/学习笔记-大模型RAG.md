# 学习笔记：大模型 RAG

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是在大模型回答前，
先从外部知识库检索相关内容，再基于检索结果生成回答的技术。核心价值是
解决大模型的知识过期和幻觉问题。

## 核心流程

1. 文档加载与清洗
2. 文本切分（chunk），保留章节结构便于引用
3. 向量化（embedding）并存入向量数据库
4. 用户提问时向量检索 top-k 候选
5. 精排（rerank）筛选最相关内容
6. 拼接上下文交给大模型生成带引用的回答

## 关键经验

- 切分块大小 512 字符、重叠 64 字符是常用起点，需按内容调优
- 检索召回率不足时，优先尝试查询改写而不是加大 top-k
- 重排序对中文问答准确率提升显著，值得引入
- 引用来源元数据（文档名、章节）必须随 chunk 一起保存

## 常见坑

- 向量检索结果与问题无关却得分高 —— 需要精排兜底
- 切分破坏 markdown 表格 —— 优先用 MarkdownHeaderTextSplitter
- 文档删除后索引不清理 —— 需做增量索引与删除同步
